# M2: разбор чека

Ответственный: Даниил Горляков. Пакет: `extract/`.

M2 получает от M1 распознанные фрагменты текста с координатами (`OcrResult` из `common/ocr.py`) и возвращает чек (`Receipt` из `common/contracts.py`): магазин, дату, итог, позиции и предупреждения. Категории позиций M2 не определяет, это делает M3.

## Публичные функции

| Функция | Вход | Что делает |
|---|---|---|
| `extract.parse_ocr_result` | `OcrResult` | основной разбор: собирает строки по координатам и связывает название позиции с её суммой |
| `extract.parse_receipt` | обычный текст | разбор без координат, для текста из других источников и тестов |
| `extract.agent.parse_with_agent` | `OcrResult` | то, что вызывает пайплайн M4: разбор правилами плюс необязательные языковые модели (ниже) |

## Как устроен разбор правилами

| Файл | Назначение |
|---|---|
| `layout.py` | собирает фрагменты OCR в строки по их положению на чеке |
| `parser.py` | магазин, дата, итог; точка входа разбора |
| `item_region.py` | находит область позиций между шапкой и итогом, отсекает служебные строки |
| `items.py`, `layout_items.py` | разбор строк позиций: название, количество, цена, сумма |
| `validation.py` | сверка арифметики: количество × цена и сумма позиций против итога |
| `_text.py` | общие регулярные выражения для дат, сумм и меток итога |

Проблемы, которые не мешают сохранить чек, попадают в `Receipt.warnings`. Коды описаны в `ReceiptWarning` (`common/contracts.py`), например `items_incomplete` и `items_total_mismatch`.

## Языковые модели (необязательно)

`parse_with_agent` всегда сначала разбирает чек правилами.

- **Локальная модель Ollama.** Если в разборе есть предупреждения, текст отправляется в локальную модель (`OLLAMA_HOST`, по умолчанию `http://localhost:11434`; модель `OCR_REVIEW_MODEL`, по умолчанию `qwen2.5:1.5b-instruct-q4_K_M`). Её ответ принимается, только если значения подтверждаются текстом чека и разбор получается лучше. Если Ollama недоступна, используется результат правил.
- **Внешний сервис OpenKilo.** Если задан `KILO_API_KEY` (или `KILO_TOKEN`), текст чека отправляется на `ai-gateway.kilo.ai`. Это передача содержимого чека во внешний сервис, поэтому по умолчанию переменная пустая.

## Инструменты

```bash
# Проверка распознанного текста локальной моделью; ничего не сохраняет
uv run python -m extract.review path/to/receipt-ocr.txt

# Оценка разбора на размеченных примерах (JSONL с полями id, ocr, expected)
uv run python -m extract.eval_extract --input samples.jsonl --timezone Europe/Moscow
```

`review.py` выдаёт JSON с предложенными исправлениями и флагом `safe_to_apply`. Исправления — только подсказки, сохранённые чеки он не меняет. Формат размеченных примеров описан в `samples.py`, метрики — в `evaluation.py`.
