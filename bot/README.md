# M4: бот, пайплайн и хранилище

Ответственный: Андрей Карабанов. Пакеты: `bot/`, `pipeline/`, `storage/`.

M4 принимает фото чека в Telegram, по очереди вызывает остальные модули, сохраняет результат и отвечает пользователю. Сам M4 не распознаёт текст, не разбирает чек и не определяет категории: это делают M1, M2 и M3.

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | приветствие |
| `/help` | справка |
| `/month` | расходы за текущий месяц: сумма, число чеков и разбивка по категориям |
| `/month MM.YYYY` | то же за выбранный месяц, например `/month 11.2025` |
| `/history` | последние 5 чеков: дата, магазин, сумма |
| `/undo` | удалить последний сохранённый чек |
| фото или файл-изображение | распознать, разобрать и сохранить чек |

Бот отвечает на русском или английском, по языку интерфейса Telegram. Все тексты лежат в `bot/texts.py`.

## Путь чека

1. **Приём.** Бот скачивает фото в максимальном разрешении или файл-изображение. Файлы больше 20 МБ не скачивает: Bot API их не отдаёт. Пока идёт обработка, бот показывает статус «печатает…».
2. **Распознавание (M1).** Пайплайн по очереди запускает движки OCR из `ocr.build_ocr_engines`. Если включён Hunyuan OCR и его результат удалось разобрать, берётся он. Иначе из всех кандидатов выбирается лучший разбор: найдены дата и итог, сходится сумма позиций.
3. **Разбор (M2).** `extract.agent.parse_with_agent` разбирает текст правилами. Если остались предупреждения, он пробует локальную модель Ollama, а при заданном `KILO_API_KEY` — внешний сервис OpenKilo (см. `extract/README.md`).
4. **Проверка.** Если на чеке нет ни даты, ни итога, чек не сохраняется, и бот просит переснять фото.
5. **Категории (M3).** Если модель `categorize/models/category_transformer` загрузилась при старте, каждая позиция получает категории. Если модели нет или классификатор упал, чек сохраняется без категорий.
6. **Сохранение.** Чек записывается в SQLite. Если такой чек уже есть (тот же магазин, дата и итог), бот не сохраняет его сразу, а спрашивает кнопками: сохранить ещё раз или нет.

Ответы на ошибки:

| Ситуация | Ответ бота |
|---|---|
| фото не открывается или на нём нет даты и итога | просьба переснять |
| изображение больше лимита OCR в пикселях | просьба уменьшить |
| сбой движка OCR | «распознавание временно недоступно», подробности только в логе |
| часть позиций не разобрана | предупреждение, что список может быть неполным |
| сумма позиций не сходится с итогом | предупреждение и совет удалить чек через `/undo` |

Для каждого чека в лог пишется время распознавания, разбора и сохранения.

## Месяц и повторы

- Чек относится к месяцу по дате на нём, а если дата не распознана, то по времени отправки фото.
- Границы месяца считаются в часовом поясе `BOT_TIMEZONE`, а не в UTC.
- Чеки без итога учитываются в числе чеков, но не в сумме.
- Чек, ожидающий ответа на вопрос о повторе, хранится в памяти бота. После перезапуска кнопка ответит, что чек уже не найти, и его нужно прислать заново.

## Файлы

| Файл | Назначение |
|---|---|
| `bot/__main__.py` | точка входа: загрузка модели M3, сборка OCR и пайплайна, меню команд, запуск |
| `bot/handlers.py` | обработчики команд, фото и кнопок |
| `bot/service.py` | интерфейс `ReceiptService`, через который бот обращается к пайплайну |
| `bot/texts.py` | тексты на двух языках и оформление ответов |
| `bot/middleware.py` | выбор языка для каждого сообщения и нажатия кнопки |
| `bot/config.py` | настройки бота из `.env` |
| `pipeline/receipt.py` | порядок этапов, обработка ошибок, повторы, итоги за месяц, история |
| `storage/receipts.py` | интерфейс `ReceiptStorage` и реализация на SQLite |

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | нет, обязательна | токен бота от @BotFather |
| `BOT_TIMEZONE` | `Europe/Moscow` | часовой пояс для времени на чеках и границ месяца |
| `BOT_DATABASE_PATH` | `receipts.sqlite` | файл базы SQLite |
| `BOT_API_PROXY` | пусто | прокси для доступа к Telegram, если прямого доступа нет |

Настройки OCR (`OCR_*`) и разбора (`OLLAMA_HOST`, `OCR_REVIEW_MODEL`, `KILO_API_KEY`) описаны в `ocr/README.md` и `extract/README.md`.

## Запуск и тесты

```bash
cp .env.example .env   # вписать BOT_TOKEN
uv run python -m bot
uv run pytest tests/bot tests/pipeline tests/storage
```

Полная инструкция по установке: [docs/RUN.md](../docs/RUN.md). Ход разработки M4 по итерациям: [docs/m4/README.md](../docs/m4/README.md).
